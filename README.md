**Прослойка между LM Studio и Telegram** для self-hosted ассистента: любая скачанная в LM Studio модель запускается командой из Telegram, ответы приходят стримом.

---

## ✨ Особенности

- **🎛 Управление кнопками** — внизу экрана постоянная панель «🤖 Модели · 💬 Чаты · ⚙️ Настройки»; всё остальное — inline-кнопки внутри панелей, команды не нужны
- **🤖 Свободный выбор модели** — список скачанных моделей берётся прямо из LM Studio, запуск одним нажатием. Никаких заранее прописанных моделей
- **1️⃣ Всегда запущена одна модель** — при запуске новой остальные LLM автоматически выгружаются
- **💬 Именованные чаты** — каждый чат хранит свой отдельный контекст; их можно создавать, называть, переименовывать, переключать, очищать и удалять
- **⚡ Стриминг в реальном времени** — сообщение обновляется по мере генерации (каждые 1.5 сек для защиты от лимитов Telegram)
- **👥 Несколько администраторов** — `ADMIN_IDS` через запятую, у каждого своя история чатов
- **👁 Поддержка изображений** — фото отправляется прямо в модель, если она умеет vision (👁 в списке)
- **🧠 Показ «мыслей» модели** — `reasoning_content` от LM Studio, а также теги прямо в тексте ответа: `<think>…</think>` (Qwen3, DeepSeek-R1 и др.) и `<|channel>thought…<channel|>` (**Gemma 4**). Переключатель в настройках
- **✂️ Длинные ответы** разбиваются на несколько сообщений, Markdown ответа конвертируется в форматирование Telegram
- **🔒 Безопасность** — бот и его кнопки работают только для администраторов из `ADMIN_IDS`

## 🚀 Быстрый старт

### 1. Требования

| Компонент | Версия | Ссылка |
|-----------|--------|--------|
| **Python** | 3.10+ | [python.org](https://python.org) |
| **LM Studio** | 0.4.0+ | [lmstudio.ai](https://lmstudio.ai) |
| **Telegram** | Аккаунт | [telegram.org](https://telegram.org) |
| **Git** | Любой | [git-scm.com](https://git-scm.com) |

### 2. Установка

```bash
# Клонируем репозиторий
git clone https://github.com/dextray765/lms-to-telegram-fork.git
cd LmStudio-To-Telegram-bot

# Создаём виртуальное окружение
python3 -m venv venv
source venv/bin/activate  # Linux/Mac
# venv\Scripts\activate   # Windows

# Устанавливаем зависимости
pip install -r requirements.txt
```

### 3. Настройка

```bash
# Копируем шаблоны конфигурации
cp .env.example .env
cp config.json.example config.json

# Редактируем параметры
nano .env
```

**Обязательные параметры в `.env`:**

```ini
# === TELEGRAM ===
TELEGRAM_TOKEN=ваш_токен_бота_от_@BotFather
# Один или несколько Telegram ID через запятую (узнать свой: @userinfobot)
ADMIN_IDS=111111111,222222222

# === LM STUDIO ===
LM_STUDIO_URL=http://localhost:1234
LM_API_TOKEN=ваш-токен-LMStudio
```

Остальные параметры (`TIMEOUT`, `LOAD_TIMEOUT`, `LOG_LEVEL`, `ENABLE_VISION`, `ENABLE_STREAMING`, `TEMPERATURE`, `MAX_HISTORY`, `STREAM_UPDATE_INTERVAL`, `CONTEXT_LENGTH`) необязательны и описаны в `.env.example`.

**`config.json` (необязателен)** содержит один параметр — `system_prompt`, системный промпт для всех чатов. Без файла используется нейтральный промпт «You are a helpful assistant».

### 4. Запуск

```bash
chmod +x run.sh
./run.sh
```

Скрипт автоматически:
- ✅ Создаст `config.json` из примера, если его нет
- ✅ Создаст/активирует venv (пересоздаёт только при смене версии Python)
- ✅ Установит зависимости — только при первом запуске или после изменения `requirements.txt`, поэтому бот стартует и без интернета
- ✅ Проверит LM Studio; если сервер не запущен и установлен CLI `lms` — запустит его и дождётся API (до 45 сек)
- ✅ Запустит Telegram бота

## 🎛 Управление

Отправьте боту `/start` (или `/menu`) — внизу появится постоянная панель из трёх кнопок. Любой другой текст — это сообщение модели в текущем чате.

### 🤖 Модели
Показывает все скачанные в LM Studio LLM (по 6 на странице, листается ◀️ ▶️):
🟢 запущена · ⭐ выбрана, но не запущена · ⚪ не запущена · 👁 умеет читать изображения.

**Нажмите на модель — она запустится**, все остальные LLM выгрузятся (embedding-модели не трогаются). Одновременно работает только одна. Панель сама обновится и покажет результат; если загрузка не удалась, останется прежний выбор и появится сообщение об ошибке. «🔄 Обновить» перечитывает список из LM Studio.

Выбор общий для всех администраторов и сохраняется между перезапусками. Если модель не выбрана, бот использует ту, что уже запущена в LM Studio; если модель выгрузили вручную, бот сам запустит её заново при следующем сообщении.

### 💬 Чаты
Список чатов: номер, имя, число сообщений, время последней активности и последний вопрос; текущий отмечен ✅. У каждого чата две кнопки:

| Кнопка | Что делает |
|--------|-----------|
| имя чата | Сразу переключает на этот чат |
| ⚙️ | Открывает карточку чата: **✅ Сделать текущим**, **✏️ Переименовать**, **🧹 Очистить** (история; сам чат остаётся), **🗑 Удалить** |
| ➕ Новый чат | Бот просит прислать имя сообщением. Кнопка «Без имени» создаст `Chat 2`, `Chat 3`…, «✖ Отмена» вернёт к списку |

- Сообщения всегда попадают в *текущий* чат, и модель видит только его историю — чтобы разные темы не смешивались, заводите отдельный чат под каждую.
- Очистка и удаление требуют подтверждения кнопкой («Да» / «Нет»).
- Имя — до 32 символов, можно с пробелами и кириллицей. Пустое имя, имя из одних цифр и дубликат (без учёта регистра) отклоняются с пояснением, при этом бот продолжает ждать другое имя.
- Ожидание имени отменяется нажатием любой другой кнопки, фото или через 5 минут — после этого текст снова считается обычным сообщением модели.
- Удалять можно любой чат, включая `Main`. Если удалён текущий, бот переключится на чат с самой свежей перепиской; если не осталось ни одного — создаст новый `Main`.
- Чаты хранятся в `sessions.json` отдельно для каждого администратора; в истории остаётся до `MAX_HISTORY` последних сообщений (по умолчанию 40).

### ⚙️ Настройки
Сводка (чат, модель, стриминг, фото) и два действия для текущего чата: **💭 Мысли ВКЛ/ВЫКЛ** (показывать размышления модели; настройка своя у каждого чата) и **🧹 Очистить историю**.

### 🖼 Изображения
Отправьте фото (с подписью или без) — оно уходит в модель вместе с вопросом. Если выбранная модель не умеет vision, бот скажет об этом и не будет её нагружать — выберите модель с 👁. В историю чата попадает пометка `[изображение]`, а не сама картинка.

- ✅ Доступ только у пользователей из `ADMIN_IDS`; остальным бот не отвечает (кроме отказа на `/start`), нажатия кнопок от посторонних блокируются
- ✅ Все конфигурации хранятся локально
- ✅ Нет отправки данных на внешние серверы
- ✅ `.env`, `config.json` и `sessions.json` в `.gitignore` — токены и переписка не попадут в репозиторий

> ⚠️ **Важно:** Никогда не коммитьте `.env` и `sessions.json` в Git!

## ⚠️ Важные примечания

1. **Длина контекста** — настройте её в интерфейсе LM Studio или задайте `CONTEXT_LENGTH` в `.env` (применяется при запуске модели ботом).
2. **Стриминг** — обновляет сообщение каждые 1.5 секунды для защиты от `429 Too Many Requests`.
3. **Загрузка модели** — пока модель грузится, бот обрабатывает остальные нажатия и сообщения по очереди; лимит ожидания — `LOAD_TIMEOUT`.
4. **Python 3.14+** — проект протестирован на Python 3.14 (Arch Linux). Нужен `python-telegram-bot` 21.10 или новее (так указано в `requirements.txt`).
5. **Размышления моделей.** Бот понимает два способа:
   - LM Studio сам отделяет размышления в поле `reasoning_content` (настройка «Reasoning Section Parsing» в параметрах модели и опция выделения `reasoning_content` в настройках сервера, если она есть в вашей версии LM Studio) — тогда ничего делать не нужно;
   - теги остаются прямо в тексте ответа: `<think>…</think>` или `<|channel>thought…<channel|>` у Gemma 4 — бот вырежет их сам. Служебная метка `thought` в начале блока Gemma тоже убирается.

   Если у модели с размышлениями (например, Gemma 4 из стороннего GGUF) разбор не настроен и LM Studio вдобавок скрывает служебные токены, то в ответе не остаётся тегов, по которым можно отделить мысли, и они попадут в текст. В этом случае в параметрах модели в LM Studio задайте разбор: начало `<|channel>thought`, конец `<channel|>`. Включать и выключать сам режим размышлений (поле «Enable Thinking» у Gemma 4) нужно в LM Studio, бот им не управляет. В историю чата размышления не попадают: туда сохраняется только ответ.
6. **Длинные ответы** — автоматически разбиваются на несколько сообщений (лимит Telegram — 4096 символов).

## 🛠️ Интеграция с веб-поиском (опционально)

Можно подключить локальный поиск через MCP:

1. Склонируйте [web-search-mcp](https://github.com/lmstudio-ai/web-search-mcp)
2. Настройте `~/.cache/lm-studio/mcp.json`:

```json
{
  "mcpServers": {
    "web-search": {
      "command": "node",
      "args": ["/полный/путь/web-search-mcp/dist/index.js"],
      "env": {
        "MAX_BROWSERS": "1",
        "BROWSER_HEADLESS": "true",
        "DEFAULT_TIMEOUT": "20000"
      }
    }
  }
}
```

3. Перезапустите LM Studio

## ❓ Частые проблемы

| Проблема | Решение |
|----------|---------|
| `Модель не найдена` / `Модель не выбрана` | Нажмите «🤖 Модели» и выберите модель из списка |
| `429 Too Many Requests` | Стриминг автоматически ограничивает обновления (1 раз в 1.5 сек) |
| `Connection refused` | Запустите сервер LM Studio (вкладка Developer) или `./run.sh` — он попробует сделать это через `lms` |
| `Python 3.14 ошибка asyncio` | Убедитесь что `python-telegram-bot` версии 21.10 или новее |
| Бот не принимает изображения | Нужна модель с пометкой 👁 в разделе «🤖 Модели» и `ENABLE_VISION=true` |
| `ModuleNotFoundError` | Запустите `pip install -r requirements.txt` внутри venv |

## 📋 Список изменений

### Новое поведение и функции

- **Размышления Gemma 4.** У Gemma 4 формат другой: `<|channel>thought\n…размышление…<channel|>ответ`. Бот вырезает такие блоки из ответа и показывает как «мысли» (переключатель «💭 Мысли» в настройках), в том числе:
  - когда блок приходит по частям при стриминге: недописанные теги не мелькают, пока модель думает, вместо текста показывается «🧠 Думаю…»;
  - когда у модели пустой канал размышлений (большие модели Gemma 4 иногда выдают его при выключенном режиме);
  - когда блоков несколько (вызовы инструментов) или в тексте остался только закрывающий тег;
  - когда LM Studio уже отделил размышления в `reasoning_content`, но оставил в начале служебную метку `thought`.

  Форматы описаны таблицей `_THINK_FORMATS` в `bot.py`; новый формат добавляется одной строкой (пара регулярных выражений «открывающий тег / закрывающий тег»).

- **Управление полностью на кнопках.** Слэш-команды (`/models`, `/model`, `/chats`, `/new`, `/switch`, `/rename`, `/delete`, `/reset`, `/think`, `/status`) убраны. Остались только `/start` и `/menu`, которые показывают постоянную панель из трёх кнопок («🤖 Модели», «💬 Чаты», «⚙️ Настройки»). Всё остальное делается inline-кнопками в панелях, сообщения-панели редактируются на месте, не засоряя переписку. Единственное место, где нужен текст, — ввод имени чата.
- **Панель «Модели»:** список из LM Studio с пагинацией, пометки 🟢/⭐/⚪/👁, запуск одним нажатием. Кнопки хранят короткий хэш ключа модели, а не её индекс, поэтому устаревший список не может запустить не ту модель (бот сообщит, что список устарел, и обновит его).
- **Панель «Чаты»:**
  - Переключение одним нажатием на имя чата; ⚙️ открывает карточку (текущим, переименовать, очистить, удалить).
  - Создание чата с вводом имени или кнопкой «Без имени».
  - Подтверждение кнопками для очистки и удаления.
  - Чаты получили стабильные короткие id (хранятся в `sessions.json`), поэтому кнопки продолжают работать после переименования, а длинные кириллические имена не упираются в лимит Telegram 64 байта на данные кнопки.
  - Имена проверяются: пустые, длиннее 32 символов, из одних цифр и дубли без учёта регистра отклоняются с пояснением (раньше длинное имя молча обрезалось).
  - Ожидание имени отменяется любой другой кнопкой, фото или по таймауту 5 минут, так что обычное сообщение не станет именем случайно.
  - `Main` больше не особенный: его можно переименовать и удалить. После удаления текущего чата выбирается самый свежий, а при удалении последнего создаётся новый `Main`.
  - Чаты хранят время создания и последней активности (в старых `sessions.json` их нет, там показывается «—»).
  - Автоматические имена теперь `Chat 2`, `Chat 3` (раньше `Chat_2`); существующие чаты со старыми именами продолжают работать.
- **Панель «Настройки»:** сводка и переключатель показа «мыслей» для текущего чата.
- **Модели берутся из LM Studio, а не из `config.json`.** Раздел `models` в конфиге удалён. Список скачанных моделей запрашивается через Native API LM Studio, запуск — нажатием кнопки. Если Native API недоступен, используется OpenAI-совместимый `/v1/models` (модель тогда загружает сам LM Studio).
- **Всегда запущена только одна модель.** Выгрузка остальных LLM стала обязательной (параметр `UNLOAD_OTHER_MODELS` удалён); лишние экземпляры той же модели тоже выгружаются.
- **Выбор модели общий и сохраняется** в `sessions.json` между перезапусками. Если выбор не сделан — используется уже запущенная модель.
- **Несколько администраторов:** `ADMIN_IDS=1,2,3` вместо одного `ADMIN_ID` (старая переменная `ADMIN_ID` продолжает читаться). У каждого администратора свои чаты. Старый `sessions.json` автоматически переносится первому администратору из списка.
- **Vision без отдельной модели.** Раньше бот просил отдельную vision-модель описать картинку, затем возвращал основную. Теперь картинка отправляется прямо в выбранную модель, если она умеет vision; иначе бот сообщает об этом и ничего не загружает.
- **`config.json`** теперь содержит только `system_prompt` и необязателен.
- **Markdown ответа модели** конвертируется в форматирование Telegram (жирный, курсив, код, ссылки, списки); если Telegram отклоняет разметку, ответ отправляется простым текстом. Блок «мыслей» оформляется сворачиваемой цитатой.
- Появились необязательные параметры `.env`: `TEMPERATURE`, `MAX_HISTORY`, `STREAM_UPDATE_INTERVAL`, `CONTEXT_LENGTH`; параметр `LOG_LEVEL` теперь действительно работает, `LOAD_TIMEOUT` добавлен для долгой загрузки моделей.

### Удалено

- **Конфигурируемая клавиатура** из `config.json` (`ui.keyboard`) и кнопки режимов. Вместо них — фиксированная панель «Модели / Чаты / Настройки», модели берутся из LM Studio.
- **Режимы/пресеты** (`models`, `prompts` и привязка кнопок к моделям в `config.json`).
- **RP-функции:** кнопки и состояния «RP Setup», «Show RP», «Clear RP», сценарии `custom_rp`.
- **Убийца браузера** (`browser_killer`): в исходной версии выполнялись `pkill -f chrome` и `pkill -f chromium`, которые закрывали любой Chrome/Chromium на машине, включая обычный браузер пользователя, и повторялись каждую минуту. Функция удалена целиком вместе с параметрами `BROWSER_TTL`, `BROWSER_KILLER`, `BROWSER_KILL_PATTERN`.
- Параметр `UNLOAD_OTHER_MODELS` и отдельная vision-модель (`models.vision`, промпт `vision`).

### Исправленные ошибки

- **Бот не запускался:** в `post_init` использовался неимпортированный `Application` (`NameError`).
- **Потеря ответа:** если финальный текст совпадал с последним стриминговым обновлением, Telegram отвечал «message is not modified»; бот показывал ошибку и не сохранял ответ в историю.
- **Ответы длиннее 4096 символов** обрезались или не отправлялись — теперь делятся на несколько сообщений (с корректным закрытием блоков кода).
- **Размышления модели:** теперь читается `reasoning_content`; теги `<think>` обрабатываются и при наличии только закрывающего тега.
- **Падение стриминга** на финальном чанке без `choices` (с `usage`) и необработанные ошибки внутри потока.
- **Новый чат мог затереть существующий:** имя `Chat_N` считалось по количеству сессий и могло совпасть с занятым.
- **Падение при правке сообщения:** редактирование старого сообщения вызывало обработчик, где `update.message` пуст.
- **Слишком короткое ожидание загрузки модели** (6 секунд) заменено ожиданием ответа API (синхронный запрос `models/load`, лимит `LOAD_TIMEOUT`); при отказе `flash_attention` загрузка повторяется без него.
- **Идентификатор модели:** для запросов используется `instance_id`, который возвращает LM Studio, а не угаданный путь.
- **Ошибки API** показывались как `b'...'` — теперь читаемый текст.
- **Файл состояния** пишется атомарно; повреждённый сохраняется как `sessions.json.bak`, а не затирается.
- **Некорректные значения `ADMIN_ID` / `ADMIN_IDS`** (не числа) пропускаются с предупреждением в логе и больше не роняют бота; без единого корректного ID бот сообщает об этом и не запускается.
- Добавлен общий обработчик ошибок; из лога убраны URL запросов httpx.
- Системный промпт больше не привязан к жёстко прописанному режиму `sophia`.

### Скрипты и файлы

- **`run.sh`:**
  - читает `.env` (раньше токен LM Studio не учитывался), не удаляет `venv` при каждом запуске (пересоздаёт только при смене версии Python), создаёт `config.json` из примера, действительно пытается запустить сервер через `lms server start` и ждёт API до 45 секунд (README это обещал, скрипт — нет);
  - значения `LM_STUDIO_URL` и `LM_API_TOKEN` читает тем же парсером, что и бот (`python-dotenv`), поэтому кавычки и комментарии в `.env` понимаются одинаково;
  - не выполняет `pip install --upgrade pip` при каждом запуске и ставит зависимости только при изменении `requirements.txt` — иначе без интернета скрипт падал, даже когда всё уже установлено;
  - файл `.env` не обязателен, если `TELEGRAM_TOKEN` передан переменными окружения (например, через systemd);
  - проверяет наличие `python3` и `curl`, даёт понятную подсказку, если не хватает пакета `python3-venv`, и хранит только 20 последних логов запуска.
- **Добавлены** `.env.example` (README ссылался на него, но файла не было) и `.gitignore`.
- **`requirements.txt`:** `python-telegram-bot>=21.10,<23`, `httpx>=0.27,<0.29`, `python-dotenv>=1.0.1` вместо жёстких версий.
- **README** переписан под новое поведение (убраны упоминания RP, `VISION_ID` и режимов; описаны кнопочные панели).

### Проверка кода и полировка

Полный проход по коду; на каждый пункт написан регрессионный тест.

- **Выбор модели:** после запуска модели панель всегда возвращалась на первую страницу списка. Теперь остаётся страница с выбранной моделью.
- **Ответ мог пропасть:** если статусное сообщение («Генерация…») удалить во время ответа, редактирование не удавалось и ответ терялся. Теперь порядок попыток такой: HTML → простой текст → новое сообщение. При сетевой ошибке повторной отправки нет, чтобы не создавать дубли.
- **Форматирование:** `md_to_html` съедал пустую строку после заголовка и мог захватывать перевод строки после маркера списка; регулярные выражения исправлены.
- **Стриминг:** недописанный тег (`<thi…`) больше не мелькает в предпросмотре ответа.
- **Кнопки:**
  - нажатие на слишком старое («недоступное» для Telegram) сообщение показывает подсказку вместо падения;
  - непредвиденная ошибка внутри кнопки теперь выводится сообщением, а не оставляет панель на «Запускаю…».
- **Загрузка моделей:**
  - при ошибке 5xx (например, не хватило памяти) бот больше не пробует вторую тяжёлую загрузку без `flash_attention`: повтор только для 400/422;
  - неудачная выгрузка логируется;
  - некорректный JSON от LM Studio превращается в понятную ошибку.
- **Ошибки API:** некорректный ответ модели даёт понятное сообщение; при переполнении контекста бот подсказывает очистить историю чата или увеличить контекст в LM Studio.
- **Файл состояния:**
  - при чтении проверяются типы: битые сообщения, нечисловые метки времени, повторяющиеся id, пользователи с повреждёнными данными пропускаются, а не роняют весь файл;
  - имя чата всегда берётся из ключа (раньше рассинхрон мог оставить «текущий чат» ненайденным);
  - `sessions.json` создаётся с правами `600`, потому что в нём личная переписка.
- **Настройки `.env`:** значения ограничены разумными пределами (`MAX_HISTORY` ≥ 2, `STREAM_UPDATE_INTERVAL` ≥ 0.5 с, `TEMPERATURE` 0–2, `TIMEOUT` ≥ 10 с, `LOAD_TIMEOUT` ≥ 30 с, `CONTEXT_LENGTH` ≥ 0), чтобы опечатка (`MAX_HISTORY=0`) не ломала бота.
- **Логи:** `bot_debug.log` вращается (до 1 МБ × 3 файла) и не растёт бесконечно; обрывы связи с Telegram пишутся предупреждением без трейсбека; сбой индикатора «печатает» не срывает обработку сообщения.
- Удалён неиспользуемый код (`reply_plain`, поиск чата по имени из времён команд).
